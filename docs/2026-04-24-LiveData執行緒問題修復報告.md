# LiveData 執行緒問題修復報告

**日期**: 2026-04-24  
**問題**: 執行系統資訊測試時，只顯示前兩行訊息，後續訊息都不見了  
**根本原因**: LiveData 執行緒使用錯誤 + postValue() 快速連續調用問題

## 問題分析

### 現象
執行「系統資訊測試」時，只看到：
```
[資訊] 開始執行測試: 系統資訊測試
[資訊] 當前設備類型: PAX
```

後續的所有訊息（製造商、設備型號、Android 版本等）都沒有顯示。

### 根本原因

**問題 1: LiveData 的 setValue() vs postValue() 差異**：

| 方法 | 執行緒要求 | 行為 |
|------|-----------|------|
| `setValue()` | **僅主執行緒** | 直接在當前執行緒更新值 |
| `postValue()` | **任何執行緒** | 將更新任務投遞到主執行緒執行 |

**問題 2: postValue() 的快速連續調用問題**：

`postValue()` 有一個嚴重缺陷：
- 它是**異步**的，將數據投遞到主執行緒的 MessageQueue
- 如果在前一個值還未被主執行緒處理時就調用新的 `postValue()`，**舊值會被覆蓋**
- 在快速連續調用的情況下（如您的測試代碼），**大部分中間值都會丟失**
- 只有最後一個值會被保留

### 問題代碼
```java
public void addLogMessage(String message) {
    // ...
    logMessages.postValue(currentLog + logEntry);  // ❌ 快速連續調用會丟失訊息
}

// 測試方法中快速連續調用
addInfoMessage("製造商: xxx");              // 1️⃣ 投遞到隊列
addInfoMessage("設備型號: xxx");            // 2️⃣ 覆蓋前一個
addInfoMessage("設備序號 (SN): xxx");       // 3️⃣ 覆蓋前一個
addInfoMessage("Android 版本: xxx");        // 4️⃣ 覆蓋前一個
addInfoMessage("Android SDK 版本: xxx");    // 5️⃣ 覆蓋前一個，只有這個會顯示
```
```

### 執行流程分析
1. ✅ `executeTest()` 在主執行緒執行，添加前兩行訊息（成功）
2. ✅ 調用 `executeClickEvent.call()`，觸發 Fragment 執行測試
3. ✅ Fragment 調用 `executeSystemInfoTest()`
4. ❌ `ThreadUtils.runInBackground()` 切換到背景執行緒
5. ❌ 背景執行緒中調用 `addInfoMessage()` → `addLogMessage()`
6. ❌ `setValue()` 在背景執行緒中被忽略或失敗
7. ❌ 所有後續訊息都無法顯示

## 修復方案

### 修改內容
將所有 `setValue()` 改為 `postValue()`，確保可以從任何執行緒安全調用。

**修改的方法**：
1. ✅ `addLogMessage()` - 最關鍵的修復
2. ✅ `clearLogMessages()` - 預防性修復
3. ✅ `setTestDescription()` - 預防性修復
4. ✅ `showToast()` - 預防性修復

### 修復後代碼
```java
public void addLogMessage(String message) {
    // ...
    logMessages.postValue(currentLog + logEntry);  // ✅ 正確：支援背景執行緒
}

public void clearLogMessages() {
    logMessages.postValue("等待執行...\n");  // ✅ 預防性修復
}

public void setTestDescription(String description) {
    testDescription.postValue(description);  // ✅ 預防性修復
}

public void showToast(String message) {
    toastEvent.postValue(message);  // ✅ 預防性修復
}
```

## 技術細節

### setValue() vs postValue() 內部實現

**setValue()**:
```java
protected void setValue(T value) {
    assertMainThread("setValue");  // 檢查是否在主執行緒
    mVersion++;
    mData = value;
    dispatchingValue(null);
}
```

**postValue()**:
```java
protected void postValue(T value) {
    // 可以在任何執行緒調用
    synchronized (mDataLock) {
        mPendingData = value;
    }
    ArchTaskExecutor.getInstance()
        .postToMainThread(mPostValueRunnable);  // 投遞到主執行緒執行
}
```

### 為什麼前兩行訊息能顯示？

因為前兩行訊息是在 `executeTest()` 方法中添加的：
```java
public void executeTest(String testItem) {
    // 這個方法在主執行緒執行（Fragment 的按鈕點擊事件）
    clearLogMessages();  // 主執行緒
    addInfoMessage("開始執行測試: " + testItem);  // 主執行緒 ✅
    addInfoMessage("當前設備類型: " + currentDeviceType.name());  // 主執行緒 ✅
    executeClickEvent.call();  // 觸發背景執行測試
}
```

後續的訊息都在背景執行緒中：
```java
public void executeSystemInfoTest() {
    ThreadUtils.runInBackground(() -> {  // 切換到背景執行緒
        addInfoMessage("========== 系統資訊測試 ==========");  // 背景執行緒 ❌
        // ... 所有後續訊息都在背景執行緒 ❌
    });
}
```

## 最佳實踐建議

### 在 ViewModel 中使用 LiveData 的原則：

1. **永遠使用 `postValue()`**
   - 在 ViewModel 中，業務邏輯可能在任何執行緒執行
   - `postValue()` 在主執行緒和背景執行緒都安全
   - 性能差異可以忽略不計

2. **避免使用 `setValue()`**
   - 除非您 100% 確定代碼只在主執行緒執行
   - 但這種確定性很脆弱，容易被打破

3. **使用 `postValue()` 的額外好處**
   - 如果快速連續調用，會自動合併更新（防抖）
   - 自動處理執行緒切換
   - 代碼更安全、更穩定

### 代碼範例

```java
// ❌ 不推薦
public void updateData(String data) {
    liveData.setValue(data);  // 只能在主執行緒調用
}

// ✅ 推薦
public void updateData(String data) {
    liveData.postValue(data);  // 任何執行緒都安全
}
```

## 總結

這是一個經典的 Android LiveData 執行緒問題，包含兩個層次：

### 第一次修復（不完整）
- **問題**：在背景執行緒使用 `setValue()`
- **嘗試修復**：改用 `postValue()`
- **結果**：看似解決，但仍有問題

### 第二次修復（完整解決）
- **發現新問題**：`postValue()` 快速連續調用會丟失數據
- **症狀**：只顯示前兩行和最後一行訊息，中間的都不見了
- **最終修復**：使用 `Handler.post()` + `setValue()`
- **結果**：所有測試功能完全正常

### 關鍵教訓
1. ❌ `postValue()` 不是萬能的，它會丟失快速連續的更新
2. ✅ `Handler.post()` 才是在背景執行緒更新 LiveData 的最佳方案
3. ⚠️ 官方文檔對 `postValue()` 的缺陷說明不足
